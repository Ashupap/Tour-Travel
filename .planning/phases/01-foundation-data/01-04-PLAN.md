# Plan 01-04: PocketBase Access Rules & Security Policies

<threat_model>
- **Threat:** Horizontal privilege escalation where an Agent views or modifies subscribers or installment collections belonging to another Agent.
  - **Mitigation:** Enforce strict PocketBase filter rule `@request.auth.role = 'agent' && agent_id = @request.auth.id` on `subscriptions` and `subscription_id.agent_id = @request.auth.id` on `installments`.
- **Threat:** Cross-territory data leakage where a Distributor inspects collections, revenue figures, or customer records outside their assigned territory.
  - **Mitigation:** Enforce distributor scoping rule `@request.auth.role = 'distributor' && distributor_id = @request.auth.id` on `subscriptions` and `subscription_id.distributor_id = @request.auth.id` on `installments`.
- **Threat:** Tampering with confirmed cash accounts where an Agent modifies installment status or amounts after physical handover to Distributor has been confirmed.
  - **Mitigation:** Enforce handover finality rule in `installments.updateRule`: prevent updates if `handover_status = 'distributor_confirmed'` unless the actor is an admin.
</threat_model>

## Objective
Apply robust zero-trust collection-level access rules in PocketBase so that agents are strictly isolated to their own records, distributors are scoped to their assigned subordinates, and confirmed handovers cannot be altered.

In `pb_migrations/1726940002_security_access_rules.js`, configure access rules for the `installments` collection:
- `listRule`: `@request.auth.role = 'admin' || (@request.auth.role = 'distributor' && subscription_id.distributor_id = @request.auth.id) || (@request.auth.role = 'agent' && subscription_id.agent_id = @request.auth.id)`
- `viewRule`: `@request.auth.role = 'admin' || (@request.auth.role = 'distributor' && subscription_id.distributor_id = @request.auth.id) || (@request.auth.role = 'agent' && subscription_id.agent_id = @request.auth.id)`
- `createRule`: `@request.auth.role = 'admin'` (Installments are auto-generated by the subscription hook)
- `updateRule`: `@request.auth.role = 'admin' || (@request.auth.role = 'agent' && subscription_id.agent_id = @request.auth.id && handover_status != 'distributor_confirmed')`
- `deleteRule`: `@request.auth.role = 'admin'`
</action>
<acceptance_criteria>
- An authenticated agent cannot view installments belonging to another agent's subscriptions.
- If `handover_status = 'distributor_confirmed'`, an update request by an agent returns HTTP 403 / is rejected.
</acceptance_criteria>
</task>
