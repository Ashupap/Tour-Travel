# Plan 01-02: PocketBase Collections Schema & Initial Migrations

<threat_model>
- **Threat:** Unconstrained user registration and privilege escalation via arbitrary `role` setting on standard auth endpoints.
  - **Mitigation:** Explicitly enforce Select options on `role` (`admin`, `distributor`, `agent`) with admin-only management rules.
- **Threat:** Orphaned installment records or negative cash accounting if subscriptions are deleted.
  - **Mitigation:** Configure relation constraint on `installments.subscription_id` with `cascadeDelete: true`.
- **Threat:** Replay or race condition in phone numbers or booking codes leading to duplicate subscription states.
  - **Mitigation:** Enforce unique database indexes on `users.phone`, `subscriptions.booking_code`, `installments.receipt_slip_id`, and index on `installments.idempotency_key`.
</threat_model>

## Objective
Create the initial schema migration script in `pb_migrations/` defining the 5 foundational collections (`users`, `packages`, `subscriptions`, `installments`, `cash_handovers`) with all field types, relations, select options, and integrity constraints as specified in the PRD.
