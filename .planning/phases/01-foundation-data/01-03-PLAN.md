# Plan 01-03: PocketBase JavaScript Hooks & Business Automation

<threat_model>
- **Threat:** Race conditions or duplicate submissions during offline synchronization leading to double-crediting or duplicate payment records.
  - **Mitigation:** Intercept installment creation/update with an idempotency check in `pb_hooks/03_idempotency.pb.js`, rejecting any collision with HTTP 400 Bad Request before database writes occur.
- **Threat:** Manual manipulation of `travel_status` by unauthorized users bypassing payment requirements.
  - **Mitigation:** Compute `paid_emis_count` and `travel_status` strictly via server-side trigger in `pb_hooks/02_installments.pb.js` querying actual paid installment records against the linked package threshold.
- **Threat:** Arithmetic rounding errors causing the sum of generated installments to differ from `total_amount`.
  - **Mitigation:** Distribute integer amounts or compute monthly installment precisely (`Math.round(total / tenure)` with remainder allocated to the first installment if necessary).
</threat_model>

## Objective
Implement PocketBase JavaScript hooks in `pb_hooks/` to automate the installment schedule generation upon subscription creation, recalculate paid EMIs and unlock travel status when installments are marked paid, and guarantee idempotent payment write operations.

<action>
Create `pb_hooks/01_subscriptions.pb.js`.
Hook into `onModelAfterCreate` (filtered for collection `"subscriptions"`):
1. Extract `tenure_months`, `total_amount`, and `booking_date` from the newly created record.
2. Calculate `monthly_amount = Math.round((total_amount / tenure_months) * 100) / 100`.
3. Locate the `installments` collection via `$app.dao().findCollectionByNameOrId("installments")`.
4. In a loop for `i = 1` to `tenure_months`:
   - Instantiate a new `Record(installmentsCollection)`.
   - Set `subscription_id` to `e.model.id`.
   - Set `installment_no` to `i`.
   - Set `amount` to `monthly_amount`.
   - Set `status` to `'pending'`.
   - Set `handover_status` to `'agent_custody'`.
   - Compute rolling due date: add `i` months to `booking_date` and format as standard ISO datetime.
   - Save the record using `$app.dao().saveRecord(installment)`.
</action>
<acceptance_criteria>
- `pb_hooks/01_subscriptions.pb.js` exists and registers an `onModelAfterCreate` hook on `"subscriptions"`.
- When a subscription with tenure 6 is created, 6 linked installment records are inserted into the database.
- Due dates of consecutive installments are staggered at 1-month intervals.
</acceptance_criteria>
</task>

<action>
Create `pb_hooks/02_installments.pb.js`.
Hook into `onModelAfterUpdate` (filtered for collection `"installments"`):
1. Check if `e.model.getString("status") === "paid"`.
2. Fetch the parent subscription record: `const sub = $app.dao().findRecordById("subscriptions", e.model.getString("subscription_id"))`.
3. Count all paid installments for this subscription using `$app.dao().findRecordsByExpr("installments", $dbx.exp("subscription_id = {:subId} AND status = 'paid'", { subId: sub.id }))`.
4. Update `sub.set("paid_emis_count", paidCount)`.
5. Fetch the package record: `const pkg = $app.dao().findRecordById("packages", sub.getString("package_id"))`.
6. Retrieve `min_emis_to_travel = pkg.getInt("min_emis_to_travel")`.
7. If `paidCount >= min_emis_to_travel` and `sub.getString("travel_status") === "locked"`:
   - Set `sub.set("travel_status", "eligible")`.
8. Save updated subscription via `$app.dao().saveRecord(sub)`.
9. Also ensure that if `paid_at` is empty when status is set to `'paid'`, automatically populate `e.model.set("paid_at", new Date().toISOString())`.
</action>
<acceptance_criteria>
- `pb_hooks/02_installments.pb.js` exists and registers an `onModelAfterUpdate` hook on `"installments"`.
- Marking an installment as `paid` increments `paid_emis_count` on the parent subscription.
- When `paid_emis_count` reaches or exceeds `min_emis_to_travel`, the subscription's `travel_status` transitions from `locked` to `eligible`.
</acceptance_criteria>
</task>

<action>
Create `pb_hooks/03_idempotency.pb.js`.
Hook into `onModelBeforeCreate` and `onModelBeforeUpdate` (filtered for collection `"installments"`):
1. Check if `e.model.getString("idempotency_key")` is populated.
2. If non-empty:
   - Query for any existing record: `$app.dao().findFirstRecordByData("installments", "idempotency_key", key)`.
   - If an existing record is found and its `id` differs from `e.model.id`:
     - Throw `new BadRequestError("Duplicate idempotency_key: " + key)`.
</action>
<acceptance_criteria>
- `pb_hooks/03_idempotency.pb.js` exists and registers before-save hooks on `"installments"`.
- Submitting an installment with an already used `idempotency_key` throws an error and halts execution.
</acceptance_criteria>
