# Plan 01-05: SQLite Analytics Views & Automated Integration Verification

<threat_model>
- **Threat:** Unauthorized access to global distributor financial aggregations or portfolio risk data.
  - **Mitigation:** Enforce view collection access rules: `admin_portfolio_overview` view accessible only by admin (`@request.auth.role = 'admin'`); `distributor_daily_analytics` view scoped so each distributor can only view their own row (`@request.auth.role = 'admin' || distributor_id = @request.auth.id`).
- **Threat:** Inaccurate analytics or NULL pointer errors due to empty relations in SQL JOINs.
  - **Mitigation:** Use `LEFT JOIN` with `COALESCE(..., 0)` so distributors with zero subscriptions or collections still return structured numeric metrics rather than NULLs.
</threat_model>

## Objective
Create the SQLite analytical views (`distributor_daily_analytics` and `admin_portfolio_overview`) as PocketBase view collections, and implement an end-to-end integration test suite `tests/phase1_verification.js` verifying all 13 Phase 1 requirements (schema, hooks, security access rules, and SQL views).
