# Plan 01-01: Project Scaffolding & PocketBase Runtime

<threat_model>
- **Threat:** Malicious or corrupted binary downloaded from arbitrary network sources.
  - **Mitigation:** Download official PocketBase v0.22.55 release specifically from GitHub releases URL using verified release archive.
- **Threat:** Accidental commit of SQLite database files (`pb_data/`), WAL journals, or binary executables to Git repository.
  - **Mitigation:** Configure a comprehensive `.gitignore` preventing `.exe`, `pb_data/`, `node_modules/`, and local test artifacts from being tracked.
</threat_model>

## Objective
Set up the standalone PocketBase v0.22.x execution environment, initialize the project directory layout, configure git ignore rules, and set up test runner scaffolding so subsequent schema migrations and hooks can execute deterministically.

## Tasks

<task>
<name>Configure Git Ignore & Project Structure</name>
<read_first>
- GEMINI.md
- PRD.md
</read_first>
<action>
Create `.gitignore` containing rules for PocketBase data (`pb_data/`), Windows executable binaries (`*.exe`), zip archives (`*.zip`), test cache files, and `node_modules/`. Ensure target directories exist: `pb_hooks/`, `pb_migrations/`, `pb_public/`, and `tests/`.
</action>
<acceptance_criteria>
- `.gitignore` exists and contains `pb_data/` and `*.exe`.
- Directory structure contains `pb_hooks/`, `pb_migrations/`, `pb_public/`, and `tests/`.
- Git status does not show any untracked `pb_data/` directory.
</acceptance_criteria>
</task>
