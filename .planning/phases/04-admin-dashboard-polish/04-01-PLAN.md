# Plan 04-01: Admin Portal Shell, Portfolio Metrics & Risk Watchlist

<threat_model>
- **Threat:** Admin APIs readable by agents, distributors, or anonymous callers exposing whole-portfolio financial data.
  - **Mitigation:** Every `/api/admin/*` route resolves the Bearer token and requires `role === 'admin'`; returns 401 without a token and 403 for any other role (`SEC-04`). The `admin_portfolio_overview` view is already admin-only at the collection-rule level.
- **Threat:** Metrics reported from a stale SQLite view row showing zeros while real cash exists in the database.
  - **Mitigation:** Read the view row first, then DAO-recompute any zero-valued metric (proven pattern from `pb_hooks/08_distributor_api.pb.js`) so numbers are always real-time correct.
</threat_model>

## Objective
Stand up the admin portal at `/admin/dashboard` with an admin-only login, portfolio health metric cards sourced from `admin_portfolio_overview` (`ADMN-01`), and a sortable post-travel default risk watchlist (`ADMN-02`).

1. `requireAdmin(c)` guard.
2. Read `admin_portfolio_overview` row (`findRecordById("admin_portfolio_overview", "portfolio_summary")` with fallback `findRecordsByExpr`).
3. DAO-recompute and override any metric that is missing/zero: `gross_portfolio_value` (sum `subscriptions.total_amount`), `total_realized_cash` (paid installments), `total_overdue_cash` (unpaid past due), `post_travel_default_count`, `field_float` (`handover_status = 'agent_custody' AND status = 'paid'`).

</action>
<acceptance_criteria>

- Agent/distributor token receives 403; no token receives 401.
</acceptance_criteria>
</task>

<task>
<name>Implement Post-Travel Default Risk Watchlist Endpoint</name>
<read_first>
- .planning/phases/04-admin-dashboard-polish/04-RESEARCH.md (Section 2)
- .planning/REQUIREMENTS.md (ADMN-02)
</read_first>
<action>
In `pb_hooks/09_admin_api.pb.js` implement `GET /api/admin/risk-watchlist`:
1. `requireAdmin(c)` guard.
2. Find subscriptions where `travel_status IN ('scheduled','completed')`.
3. For each, load installments; keep the account if >= 1 installment is `status != 'paid'` and `due_date <= now`.
4. Return rows: `booking_code`, `customer_name`, `customer_phone`, `package_title`, `travel_status`, `overdue_amount`, `overdue_count`, `max_days_overdue`, `agent_name`, `distributor_name`.
5. Support `?sort=days|amount|name&order=asc|desc` (server-side ordering; default `days desc`).
</action>
<acceptance_criteria>
- A seeded `completed` subscription with a past-due unpaid installment appears in the list.
- A `locked` subscription with the same overdue installment does not appear.
- Changing `sort` changes row order.
</acceptance_criteria>
</task>
