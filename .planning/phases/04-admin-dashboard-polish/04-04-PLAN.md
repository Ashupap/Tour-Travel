# Plan 04-04: Production Hardening & Phase 4 Verification Suite

<threat_model>
- **Threat:** Unknown browser routes returning PocketBase's raw JSON 404, degrading the branded public experience.
  - **Mitigation:** A catch-all HTML route restricted to non-`/api` and non-`/_` paths serves `pb_public/404.html` with a real 404 status, so API JSON 404 semantics are preserved for clients and tests.
- **Threat:** Phase 4 work silently regressing Phase 1–3 behavior (hooks, offline sync, landing, distributor flows).
  - **Mitigation:** `tests/phase4_verification.js` runs the full Phase 4 requirement matrix, and the Phase 1/2/3 suites are re-run as regression gates before declaring the phase complete.
- **Threat:** Deployment drift — no repeatable way to take the app to a production VPS with HTTPS.
  - **Mitigation:** Ship `docs/DEPLOYMENT.md` with exact systemd + Caddy + backup commands that have been sanity-checked against this repo's scripts (`npm run build`, `npm run pb`).
</threat_model>

## Objective
Harden the app for production (branded 404, security guidance, deployment guide) and prove all four Phase 4 requirements with an automated verification suite.
