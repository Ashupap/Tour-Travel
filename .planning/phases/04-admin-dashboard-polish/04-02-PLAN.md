# Plan 04-02: Package Manager CRUD & Live Landing Reflection

<threat_model>
- **Threat:** A non-admin mutating packages (price, active status) through the record API.
  - **Mitigation:** Collection rules already restrict create/update/delete to `@request.auth.role = 'admin'` (Phase 1); admin wrapper endpoints additionally call `requireAdmin(c)`. Verify with a negative test using an agent token.
- **Threat:** Deleting a package that customers already subscribed to, breaking booking relations and the manifest export.
  - **Mitigation:** `DELETE /api/admin/packages/:id` performs soft-deactivation (`is_active = false`) when any `subscriptions.package_id` references it; hard delete only when unreferenced. Deactivated packages vanish from the public catalog but keep historical data intact.
- **Threat:** Landing page breaks offline (or slow) after switching to server-driven packages.
  - **Mitigation:** Fetch with `filter=is_active=true`, keep the hardcoded `TOUR_PACKAGES` array as an offline/error fallback; static package images remain precached by the service worker.
</threat_model>

## Objective
Deliver full package CRUD in the admin portal — create, edit, cover-image upload, and deactivation — with changes reflecting immediately on the public landing page (`ADMN-03`).
