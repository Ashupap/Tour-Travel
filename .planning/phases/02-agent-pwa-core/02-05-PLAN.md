# Plan 02-05: Cash Handover Workflow & Phase 2 Integration Verification

<threat_model>
- **Threat:** Brute-forcing the 4-digit OTP code to falsely verify a physical cash handover.
  - **Mitigation:** Enforce distributor authentication and limit OTP verification attempts (or invalidate after repeated incorrect attempts); verify that the authenticated distributor owns the handover territory.
- **Threat:** Handing over already verified or rejected handovers.
  - **Mitigation:** Only allow verification if `handover.status === 'initiated'`; reject verification attempts on already verified or closed sessions.
</threat_model>

## Objective
Implement server-side Cash Handover initiation and OTP verification routes in `pb_hooks/05_handover_api.pb.js`, and develop a comprehensive automated integration test suite `tests/phase2_verification.js` verifying all 15 Phase 2 requirements.

<task>
<name>Implement Cash Handover Initiation Route (POST /api/handover/initiate)</name>
<read_first>
- PRD.md (Section 5.3: Handover Initiation & OTP Generation)
- .planning/phases/02-agent-pwa-core/02-RESEARCH.md (Section 1.4)
</read_first>
<action>
In `pb_hooks/05_handover_api.pb.js`, register `POST /api/handover/initiate`:
1. Authenticate agent.
2. Query all installments where `collected_by = auth.id && payment_mode = 'cash' && handover_status = 'agent_custody' && status = 'paid'`.
3. If zero eligible installments, return HTTP 400 with "No cash in custody to hand over".
4. Calculate `total_amount = sum(installment.amount)`.
5. Generate random 4-digit OTP: `String(Math.floor(1000 + Math.random() * 9000))`.
6. Retrieve agent's `distributor_id`.
7. Create a new `cash_handovers` record:
   - `agent_id = auth.id`
   - `distributor_id = agent.distributor_id`
   - `total_amount = total_amount`
   - `installments_covered = [list of installment ids]`
   - `otp_code = otp`
   - `status = 'initiated'`
   - Save via `$app.dao().saveRecord(handover)`.
8. Return JSON: `{ handover_id: handover.id, total_amount, otp_code, count }`.
</action>
<acceptance_criteria>
- `POST /api/handover/initiate` creates a `cash_handovers` record with 4-digit OTP and links all eligible cash installments.
- Returns the generated OTP and total amount to the authenticated agent.
</acceptance_criteria>
</task>

<task>
<name>Implement Cash Handover Verification Route (POST /api/handover/verify)</name>
<read_first>
- PRD.md (Section 5.3: Distributor Confirmation & State Transition)
- GEMINI.md (Key Business Rule 3: Handover finality)
- .planning/phases/02-agent-pwa-core/02-RESEARCH.md (Section 1.4)
</read_first>
<action>
In `pb_hooks/05_handover_api.pb.js`, register `POST /api/handover/verify`:
1. Authenticate distributor (or admin).
2. Extract `handover_id` and `otp_code` from request body.
3. Find `cash_handovers` record.
4. Verify that `handover.distributor_id === auth.id` (or auth is admin) and `handover.status === 'initiated'`.
5. Verify `handover.otp_code === otp_code`. If mismatch, return HTTP 400 "Invalid OTP code".
6. In a database transaction:
   - Update `handover.status = 'verified'` and `handover.verified_at = now()`.
   - Update all linked installments: set `handover_status = 'distributor_confirmed'`.
   - Save all records.
7. Return JSON: `{ success: true, message: "Handover verified successfully", total_amount }`.
</action>
<acceptance_criteria>
- Incorrect OTP is rejected with HTTP 400.
- Correct OTP transitions `cash_handovers.status` to `'verified'`.
- All linked installments transition to `handover_status = 'distributor_confirmed'`.
</acceptance_criteria>
</task>
