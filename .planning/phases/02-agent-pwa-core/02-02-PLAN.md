# Plan 02-02: PWA Engine & Dexie.js Offline Persistence Store

<threat_model>
- **Threat:** Malicious script injection or stale caching in Service Worker leading to broken sync states or cache corruption.
  - **Mitigation:** Use explicit cache versioning (`CACHE_VERSION = 'by-v1'`) and clean up older caches on Service Worker activate event.
- **Threat:** Data tampering in IndexedDB allowing field agents to manipulate local balances or receipts.
  - **Mitigation:** All financial verification and business triggers occur on the server upon sync; client IndexedDB operates strictly as a transactional local cache and outbox.
</threat_model>

## Objective
Set up the Progressive Web App infrastructure, including `manifest.json`, the Service Worker (`sw.js`) with cache-first static strategy and Background Sync event handling, and the Dexie.js offline store (`offline-store.js`) for persistent IndexedDB client storage.

<task>
<name>Implement Service Worker with Background Sync (sw.js)</name>
<read_first>
- .planning/phases/02-agent-pwa-core/02-RESEARCH.md (Section 3)
</read_first>
<action>
Create `pb_public/sw.js`:
1. Pre-cache app shell assets (`/agent/dashboard`, `/css/tailwind.css`, `/js/dexie.min.js`, `/offline-store.js`, `/manifest.json`).
2. Intercept `fetch` events with Cache-First strategy for static assets and Network-First with offline fallback for APIs.
3. Add `sync` event listener for tag `'sync-installments'`:
   - Retrieve pending entries from Dexie `outbox`.
   - POST bundle to `/api/agent/batch-sync`.
   - Mark outbox entries as synced.
   - Broadcast message `SYNC_COMPLETE` to active client windows.
</action>
<acceptance_criteria>
- `pb_public/sw.js` exists and registers `install`, `activate`, `fetch`, and `sync` handlers.
- Static assets are cached and served when network is disabled.
</acceptance_criteria>
