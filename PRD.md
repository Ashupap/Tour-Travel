Product Requirement Document (PRD)Project TitleBharatYatra PWA — Offline-First EMI-Based Bus Tour & Micro-Collection System1. Executive Summary & GoalsBharatYatra is an offline-capable Progressive Web Application (PWA) enabling fixed-route, multi-day bus tourism across India on a no-cost EMI model (6, 9, or 12 months). Customers unlock travel eligibility after paying a threshold of 2 or 3 EMIs.Physical collections and sales are executed by field agents under regional distributors. Cash reconciliation is verified by distributors before settlement. The system must operate reliably on weak 2G/3G mobile networks, support a landing page with 3D visuals, provide no-login tracking for customers, and offer analytics dashboards for distributors and admins.2. Functional Specifications & System Logic5.1 Business Automation via PocketBase Hooks (pb_hooks)Schedule Generator: On subscriptions record creation, a JS hook automatically inserts $N$ installments where amount = total_amount / tenure_months, with monthly rolling due_date intervals.Travel Unlock Engine: On installments status update to paid, calculate paid_emis_count = count(status == 'paid'). If paid_emis_count >= package.min_emis_to_travel, update subscriptions.travel_status to 'eligible'.Idempotent Insertion: Reject any incoming offline installment sync record if idempotency_key matches an existing entry.5.2 Offline Synchronization Lifecycle (Agent PWA)[Agent App Online]
  │──► 1. Trigger "Sync Morning Manifest"
  │──► 2. API queries /api/agent/sync-manifest
  │──► 3. Hydrate Dexie.js DB: 'subscriptions', 'installments'

[Agent Drops Network (Offline)]
  │──► 4. Open customer installment row
  │──► 5. Select 'Cash' -> Click 'Mark Collected'

  │         - Set status = 'paid'
  │         - Set sync_status = 'pending_push'
  │         - Generate receipt_slip_id: "OFF-{agent_id}-{timestamp}"

  │──► 8. Service Worker fires 'sync-installments' event
  │──► 9. POST payload bundle to /api/agent/batch-sync
  └──► 10. PB Hook commits records inside a single DB transaction
5.3 Cash Handover & Custody VerificationAgent EOD Trigger: Agent dashboard displays Total Cash in Hand: ₹XX,XXX. Agent taps "Handover to Distributor".OTP Generation: System updates candidate installments to handover_status = 'agent_custody', generates a random 4-digit OTP, and records the pending cash_handovers session.Distributor Confirmation: Distributor logs in, opens "Pending Handovers", inputs the 4-digit OTP provided by the physical agent, and confirms the physical cash count.State Transition: System marks the handover session as verified and transitions all linked installments to handover_status = 'distributor_confirmed'.6. The landing page must load under 1.5 seconds on 4G networks.7. Reporting & Analytical Views (PocketBase SQL Views)Distributor Dashboard View (distributor_daily_analytics)SQLSELECT 
    u.id AS distributor_id,
    COUNT(DISTINCT s.id) AS total_active_subscriptions,
    SUM(CASE WHEN i.due_date <= CURRENT_TIMESTAMP AND i.status != 'paid' THEN i.amount ELSE 0 END) AS total_overdue_amount,
    SUM(CASE WHEN i.paid_at >= date('now', 'start of day') THEN i.amount ELSE 0 END) AS collected_today,
    SUM(CASE WHEN i.handover_status = 'agent_custody' THEN i.amount ELSE 0 END) AS cash_in_agents_custody
FROM users u
LEFT JOIN subscriptions s ON s.distributor_id = u.id
LEFT JOIN installments i ON i.subscription_id = s.id
WHERE u.role = 'distributor'
GROUP BY u.id;
